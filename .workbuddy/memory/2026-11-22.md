## 日志摘要功能（1.4.0）
- 后端：`run/log/LogDigest`（DTO）+ `LogDigestParser`（纯静态，无 Spring 依赖）
  - 归一化去时间戳、识别 ##[group] 结构行
  - Rule 模型区分 primary（FAILED/##[error]/npm error）与 detail（E assert/堆栈）
  - 同类有 primary 时丢弃 detail，避免「1 个失败数成 4 处」
  - 有具体错误时 exit code 收尾行不占摘要位
  - 按归一化签名（抹平数字）去重，最多 5 条
  - 超长日志取首 500 + 末 1500 行，行号始终指向原文
- 接口：GET /api/runs/{runId}/jobs/{jobId}/logs/summary（复用全文本缓存，先看摘要再切全文不重复打 GitHub）
- 前端：StepDrawer 摘要/全文双视图，点错误条 → 切全文并 scrollIntoView 高亮（data-line 定位）
- 测试：LogDigestParserTest 19 例；后端全量 331 通过
- 教训：曾尝试「向上就近拼 traceback 断言」，导致把另一个用例的断言拼到本条错误上 → 改为只向下看 3 行

## 失败原因归类（1.5.0）
- V4 迁移：`workflow_run.failure_class` + 索引；为空 = 未归类
- `RunFailureClassifier`：失败完成时异步（虚拟线程，信号量 3）取第一个失败 job → 拉日志 → 解析 → 回写
  - 无错误日志不写库；unknown 也写库（标记已尝试，防重复下载）
  - 异常吞噬，不影响 run 状态
- `RunLogService.jobLogSummary` 顺带回写（老数据靠用户点开日志补齐）
- `FailureReasonAssembler` 纯函数做口径（百分比分母=已归类），StatsService 只负责取数
- 接口 GET /api/dashboard/failure-reasons；前端看板「失败原因分布」卡片
- 单测：Assembler 8 + Classifier 10；全量 349 通过
- 注意：WebhookEventProcessor 构造器新增依赖，改动了 WebhookEventProcessorTest 的构造调用

## 失败摘要落库 + 详情页高亮（1.6.0）
- V5 迁移：failure_job_name / failure_summary / failure_digest / failure_digest_version
- LogDigestCodec：存精简版（丢 context），VERSION 常量做规则版本，不匹配视为未命中自动重算
- RunLogService 三层读取：DB → 内存(5min) → GitHub；回源后 classifier.saveAsync 异步落库
- RunDetailDto 增加 failureClass/failureJobName/failureSummary/failureHighlights
- 前端详情页红底卡片（失败类别 + 结论 + 前 3 条错误块），未分析完时显示「分析中」
- 单测：Codec 4 + RunLogService 6；全量 359 通过
- 验证方式：关闭 mock GitHub 后摘要接口仍返回 → 证明 DB 命中
