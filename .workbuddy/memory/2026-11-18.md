# 2026-11-18 · 部署期两个线上问题修复

## 1. SSE 连接数越刷新越多（真 bug）
- 根因：`SseHub` 每次订阅 `clientId = "c" + seq++`，旧连接的清理只靠「写入失败」，而 `SseEmitter(NO_TIMEOUT)` 永不超时 → 刷新后旧 emitter 滞留。
- 修复：前端 `useRunStream` 用 sessionStorage 里的 `gl_tab_id` 作稳定 cid（`/api/stream?cid=`）；后端 `subscribe(cid)` 以 cid 为 key 原子替换并关闭旧连接；加 30 分钟兜底超时。
- 踩坑：第一版「先 remove 再 complete 再 put」会触发竞态——旧 emitter 的 onCompletion 异步执行，把同 key 的新连接删掉（日志表现为 connections 先 1 后 0）。改为 `emitters.put()` 返回旧值 + `removeIfSame(key, emitter)` 身份校验后正常。
- 验证：同 cid 连 3 次计数恒为 1；新 cid 变 2。

## 2. 添加仓库无法识别 URL（真缺陷）
- 根因：`CreateRepoRequest` 上的 `@Pattern(owner/repo)` 在 service 之前就 400；即使绕过，`indexOf('/')` 会把 `https:` 当 owner 写入脏数据。
- 修复：DTO 只留 @NotBlank/@Size；新增 `RepoService.normalizeFullName()` 支持 owner/repo、https URL、.git 后缀、/tree/main 尾巴、git@ 形式；`findByFullName` 改 `LOWER(full_name)=?` 大小写不敏感（H2 默认敏感）。
- 实测 5 种输入全部正确，大小写不同的重复接入返回 409。
