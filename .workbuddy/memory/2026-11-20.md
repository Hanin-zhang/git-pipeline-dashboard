## 做了什么

为 GitHub Look（Spring Boot 3.3 + Vue 3 CI/CD 看板）从零建立测试体系，并做真实链路验证。

### 后端：302 个用例（JUnit 5 + Mockito + AssertJ，全部为纯单元测试，不启动容器）
- `webhook/`：签名验签、幂等、入口服务（4xx/IGNORED/PONG/重复/队列故障）、Redis 队列、消费者重试与死信、事件处理器（started/completed/failed/push/忽略）

- `github/`：用本地 HttpServer 桩验证 REST 路径/鉴权头/错误码翻译与分页
- `stream/`、`settings/AlertNotifier`、`repo/`、`DomainModelTest`

## 修复的 3 个真实缺陷

1. **GithubApiClient 丢失 4xx/5xx 响应体**：`SimpleClientHttpRequestFactory`(HttpURLConnection) 拿不到错误流，
   导致 README 承诺的「（GitHub 返回：xxx）」永远为空，403 权限问题无法自查。
   → 改用 `JdkClientHttpRequestFactory` + `HttpClient.connectTimeout`，`setReadTimeout`。
2. **概览页 SSE 只刷一半**：`DashboardView.scheduleRefresh()` 只拉 summary/trend，
   工作流健康度与耗时对比停在旧值，同屏出现「失败 1 次」但「失败率 0.0%」。→ 一并刷新 workflows。
3. **`<Commit />` 图标不存在**（Element Plus 无此图标）：运行详情页控制台报
   `Failed to resolve component: Commit`。→ 换成 `Tickets`。
4. 附带修正：设置页三个通知渠道共用钉钉占位文案 → 按渠道给不同 placeholder。

## 验证结论（当前代码）
- 后端真实启动（H2 内存库 + Redis）：登录/鉴权/概览/趋势/筛选/详情 DAG/设置解锁/仓库增删守卫/退出 全部符合预期
- webhook 全链路：错签名 401 → 缺 delivery 400 → 202 QUEUED → 重复投递 DUPLICATE(Ignored) → SSE 收到 run.started/run.completed
- 浏览器（chrome-devtools）：登录 → 概览 → 列表 → 详情 DAG → 设置解锁，SSE 实测「不刷新页面」指标卡与健康度同步更新
