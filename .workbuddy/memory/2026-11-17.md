# 2026-11-17 · github-look 看板从零搭建

## 决策
- 持久层最终用 **MyBatis-Plus 3.5.9**（用户中途改要求，从 JPA 切换）；分页方言按 JDBC 连接自动探测（H2 → DbType.H2，其它 → MySQL）。
- 数据库：本地 H2 文件库（MODE=MySQL，`backend/data/`），MySQL 通过 DB_* 环境变量切换；Flyway 迁移 SQL 双兼容，用 `BOOLEAN`/`AUTO_INCREMENT`/独立 CREATE INDEX，不写 ENGINE 与内联 KEY。
- 前端 Vue 3 + Vite 6 + Element Plus + ECharts（按需注册 core 组件，减小包体）。
- 认证：JWT 存 httpOnly + SameSite=Lax Cookie（不用 localStorage / URL），EventSource 因此天然带凭据。
- 统计缓存失效用版本号（`githublook:stats:version` INCR），不用 SCAN/KEYS。
- Docker / Nginx / SSL 明确不做（用户要求跳过）。

## 踩坑记录
- H2 里 `AS day` 是保留字 → 别名必须写成 `stat_day`。
- Duration 配置 `PT50MS` 非法，Spring 只认 `PT0.05S`。
- MyBatis `<include>` 片段引用 `#{branch}` 时，mapper 方法必须声明该 @Param，否则 BindingException（workflowStats 出过）。
- zsh 不会对未加引号的变量做分词：`C="-b file"; curl $C ...` 会把整个串当成一个参数，导致 curl 静默不带 cookie。
- ResponseCookie.builder.maxAge 不接受 Duration（编译报找不到符号）。
- Composer `SSE` 不能开启 gzip，否则帧被缓冲；`text/event-stream` 已从 compression.mime-types 移除。
- 无头 Chrome 截图会触发 ~/Library 下 Google 服务文件的删除请求，被权限拦截 → 放弃截图，改用 typecheck + build + 接口冒烟验证。

## GitHub Token 配置接入（17:45）
- `app.github`：token(`${GITHUB_TOKEN:}`)、api-url、user-agent、connect/read timeout；`isConfigured()` 由 token 是否为空决定。
- 新增 `github/GithubApiClient`（RestClient + Bearer + Accept: application/vnd.github+json + X-GitHub-Api-Version: 2022-11-28），实现 rerun / cancel，按 401/403/404/409/422 分别映射成可读中文错误。
- 新增 `GET /api/capabilities` + `POST /api/runs/{id}/rerun|cancel`；未配 token 时 503，前端按钮置灰（RunHeader 用 actionsEnabled 控制）。
- 实测：无 token → capability false + rerun 503；假 token → 真实打到 api.github.com 返回 401，被映射为「GitHub Token 无效或已过期」，日志 `github_api_failed status=401`。真 token 的成功路径未验证（手上没有）。
- 安全：token 只在服务端，日志从不打印 token 内容。

## 设置页二次验证 + Docker 部署包（18:00 后）
- 门禁：`app.security.settings-password`（env `SETTINGS_ACCESS_PASSWORD`）+ `settings-token-ttl`(PT30M) + 独立 Cookie `gl_settings`。
  - JwtService 新增 `issueScoped(subject, scope, ttl)` / `parseWithScope`，settings 令牌带 `scope=settings` claim。
  - JwtAuthFilter 额外校验 settings cookie，有效则追加 `ROLE_SETTINGS_ADMIN`。
  - SecurityConfig 顺序：unlock/lock/state 仅 authenticated；`/api/settings/**` 与 `/api/repos/**` 需 hasRole('SETTINGS_ADMIN')。
  - 密码比较用 SHA-256 + MessageDigest.isEqual（常量时间）；输错走 LoginRateLimiter（key 前缀 settings:）。
- 前端 SettingsView：locked 时只渲染密码卡（不请求敏感数据），解锁后显示「剩余 X 分钟」+ 锁定按钮，30s 轮询过期自动回锁，403 时自动回锁。
- 实测 9 项：未解锁 403 / state locked / 错密码 401 / 解锁 200 / 解锁后 settings+repos 200 / lock 后 403；经 vite 代理同样正确。
- 部署包：根 `docker-compose.yml`（mysql8+redis7+backend+web，健康检查与 depends_on healthy）、`deploy/Dockerfile.backend`（多阶段 maven→JRE21 alpine，非 root）、`deploy/Dockerfile.frontend`（node→nginx）、`deploy/nginx.conf`（SPA 回退 + /api 反代 + proxy_buffering off 保 SSE）、`deploy/README.md`（手册）、`.env.docker.example`。
